## 三、1.7 实机编译验证（2026-10-14 完成）

### 3.1 1.7 目录布局的根本变化

1.6 的 `RimWorldWin64_Data\Managed\` 子目录在 1.7 中**已不存在**，所有 269 个程序集平铺在游戏根目录：

| 类别 | 1.6 | 1.7 |
|---|---|---|
| 游戏代码 | `RimWorldWin64_Data\Managed\Assembly-CSharp.dll` | `Assembly-CSharp.dll`（根目录） |
| Unity API | `UnityEngine.CoreModule.dll` 等 4+ 个模块 | **合并为 `UnityStubs.dll`**，原模块全部消失 |
| 核心库 | `mscorlib.dll`（Mono） | `System.Private.CoreLib.dll` + `System.Runtime.dll`（.NET 10） |
| 可执行文件 | `RimWorldWin64.exe`（666,624） | `RimWorld.exe`（198,656）+ `RimWorld.dll` |

### 3.2 编译过程与三处失败教训

改 `build.ps1` 支持 1.7 的引用探测，过程中踩了三个坑，均已解决：

| 尝试 | 配置 | 结果 |
|---|---|---|
| A | net471 `mscorlib` + `UnityStubs` | 满屏 `CS0012: 类型"Object"在未引用的程序集中定义，必须添加对程序集 "System.Runtime, Version=10.0.0.0" 的引用` |
| B | `/nostdlib+` + 仅 `System.Runtime.dll` | 满屏 `CS0518: 预定义类型"System.String"未定义或导入` |
| C | `/nostdlib` + `System.Private.CoreLib` **与** net471 `mscorlib` 并存 | `CS0433: 类型"AssemblyVersionAttribute"同时存在于"mscorlib"和"System.Private.CoreLib"中` + `CS0616: "HarmonyPatch"不是特性类` |
| **D（成功）** | 全部引用取自游戏根目录，用**游戏自带的** `mscorlib.dll`（net10 类型转发壳，49,152 字节） | **exit=0** |

**关键教训：`mscorlib`(net471) 与 `System.Private.CoreLib`(net10) 绝不可混用，必须整体二选一。**
1.7 游戏根目录虽仍名为 `mscorlib.dll`，但它是 net10 的类型转发壳，不是 1.6 那份 Mono 核心库。
另一个反直觉点：`System.Runtime.dll` 只是转发外壳，**不提供预定义类型**，编译器必须同时看到 `System.Private.CoreLib.dll`。

### 3.3 全库编译错误收敛结果：仅 2 个

`error CS1061: "TextEditor"未包含"ReplaceSelection"的定义` —— `AICoopLogTab.cs(102,28)`

`error CS0103: 当前上下文中不存在名称"SHA256"` —— `AICoopDlcActions.cs(291,31)`（该文件已有 `using System.Security.Cryptography;`，纯属引用列表遗漏该 dll，非代码问题）

**`UnityEngine.*` 的 5 处直接引用一处都没报错** —— `UnityStubs.dll` 完整覆盖了 `Rect` / `GUI.DrawTexture` / `ScaleMode` / `Application.wantsToQuit` / `Application.quitting`。R4 风险实测解除。

### 3.4 唯一真 API 破坏性变更：`TextEditor.ReplaceSelection`

对两个程序集做字符串扫描，双重确认：

| 符号 | `UnityStubs.dll` | `Assembly-CSharp.dll` |
|---|---|---|
| `TextEditor` | 存在 | 存在 |
| **`ReplaceSelection`** | **不存在** | **不存在** |
| `DrawTexture` / `Application` / `Rect` / `Event` / `wantsToQuit` | 存在 | — |

**这是官方"Mod 无需改动"承诺之外的一个例外：Unity 在 1.7 的 Waylith 兼容层里去掉了 `TextEditor.ReplaceSelection`。**
影响面：聊天输入框按 `Shift+Enter` 插入换行（`AICoopLogTab.cs` 的 `DrawChatPage` 内）。

修复方式（**双版本兼容**）：反射探测 + 手写兜底，见 `AICoopLogTab.cs`：

```csharp
// Unity removed TextEditor.ReplaceSelection in the Waylith-based RimWorld 1.7 runtime.
// Resolve it reflectively so one assembly keeps working on both 1.6 and 1.7+.
private static readonly System.Reflection.MethodInfo TextEditorReplaceSelection =
    typeof(TextEditor).GetMethod("ReplaceSelection", BindingFlags.Instance | BindingFlags.Public | BindingFlags.NonPublic);
```

1.7 下走兜底分支：自行按 `selectIndex` / `cursorIndex` 拼接换行并复位光标。原有 1.6 行为完全不变。

### 3.6 `RimWorld.runtimeconfig.json` —— 官方兼容承诺的技术依据

这是理解「为什么 1.7 不用改 Mod」的关键文件（`tfm` = `net10.0`）。Waylith 运行时开了一整套宽松模式专门兜住老 Mod：

| 配置项 | 兜住的风险 |
|---|---|
| `SkipAccessChecks: true` | 本 Mod 的 53 处私有成员反射（风险 R3） |
| `JitPatchableAssemblies: "Assembly-CSharp"` | 26 个 Harmony 补丁挂载（风险 R1） |
| `AssemblyNameRedirects: "UnityEngine*=UnityStubs"` | 5 处 `UnityEngine.*` 直接引用（风险 R4） |
| `MonoStringHashCode` / `MonoFloatFormatPrecision` | 对齐 Mono 的字符串哈希与浮点格式化行为 |
| `LaxPrivateFieldNames: true` | 私有字段名变化时宽松匹配 |

**注意最后一项的反面含义**：官方需要专门提供 `LaxPrivateFieldNames`，说明 1.7 的私有字段名**确实可能**与 1.6 不同。R3 必须实机逐功能验证，不能因为编译通过就认为安全。

## 四、1.7 是什么（官方原文要点）

来源：https://ludeon.com/blog/2026/10/announcing-the-waylith-engine-and-update-1-7/ （2026-10-12，Tia Young）

- 1.7 把 RimWorld 从 **Unity 迁移到自研 Waylith 引擎**，画面与玩法完全一致，性能提升 2-4x。
- 实测数据：后期殖民地 1.7 比 1.6 快 **2.2x**；1500 Mod 的整合包加载从 **14 分钟降到 6 分钟**。
- 存档：1.6 存档可在 1.7 载入，**双向兼容**（1.7 存档也能回 1.6）。
- **Mod 兼容性原文**："Your mods shouldn't need any changes to work on 1.7."（你的 Mod 无需任何改动即可在 1.7 工作）
- 出现黄色「可能不受支持」警告**仅仅是因为版本号变了**，不代表真的不兼容。
- 给 Modder 的新能力：可用最新 C# 语言特性、更容易写复杂 Mod 而不损性能。
- 1.7 目前**仅在 Steam unstable 测试分支**，主分支仍是 1.6。
- 注意：超过 10 年的老电脑可能跑不动 1.7。

### 5.5 作者已预留的版本容错

`AICoopPatches.cs:251` 有明确注释：

```
// Use positional injection because parameter names differ between RimWorld 1.6 builds.
public static void Postfix(Pawn_GuestTracker __instance, GuestStatus __1)
```

说明作者已知跨小版本参数名会变，并采用了位置注入（`__0`/`__1`）来抗变。这是个好信号，也是 1.7 适配应沿用的模式。
